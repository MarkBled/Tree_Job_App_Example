2 · What conclusion logically follows

  1. Exclusion. In mode S the facts and rules entail T_M = F for: Tjaša (a41 ≥6 yrs: progressive software engineering experience). Each such exclusion is proven by an O-input (contradiction) along the chain from atom to root.
  2. Suitability. No candidate has T_M = T. Every candidate still has mandatory atoms without evidence; for all of them, e.g., education (a50) and “enterprise-scale AI in production” (a47) are unknown. The conclusion “candidate X is suitable” therefore does not follow.
  3. Ranking (S, P3): Liam (items: 1, atoms T: 9) → Peter (items: 0, atoms T: 7) → Marko (items: 0, atoms T: 6) → Dr. Ksenija (items: 0, atoms T: 4).
  4. Mode B: excluded Dr. Ksenija, Liam, Marko, Tjaša; ranking: Peter.
  5. Conditionality. Who the priority candidate is depends on rule B1 (see 5). Both selections are logically valid, each within its own set of assumptions.

3 · What TREE’s result actually proves

  • For each of the 190 combinations (node × candidate × mode) the original propMinimization engine (parser + DNF + prime implicants) determined the contradiction or satisfiability of the corresponding formula. Agreement with an independent Python/Kleene computation: 190/190.
  • Only this is proven: if the propositions have the stated values, then rule R at that node is necessarily true (T), necessarily false (F) or undetermined (U).
  • The exclusion of Tjaša (a41 ≥6 yrs: progressive software engineering experience) is a valid consequence in mode S: whatever the unknown propositions are, the root T_M cannot be true.
  • Minimal forms (prime implicants) show the smallest sufficient combinations. Because almost all mandatory items are joined by ⋀, the requirements allow almost no substitution (the exceptions are Python ⋁ Java and Bachelor ⋁ Master).

4 · What it explicitly does NOT prove

  • It does not prove the claims in the applications are true. Applications are self-statements; none is verified by evidence (diplomas, references, tests).
  • It does not prove the interpretation of a quote is correct. The mapping “quote → proposition → level” was made by a language model using the lexicon cues_sl.json; TREE neither sees nor checks it.
  • It does not prove that Liam (or Peter) is suitable or the best candidate. The P3 ranking is a count, not an assessment, and the counting rule is not derived from the ad.
  • It does not prove that candidates lack a skill. U only means the application does not state it; a lower stated level is a lower bound, not an upper bound.
  • It does not assess attitudes or personality (obedience, criticism of MVPs, self-confidence). The ad does not require them as propositions, so they are left out (see the candidate cards).
  • It considers nothing outside the texts: CV, interview, references, work permit, location, salary.

5 · Assumptions, missing inferences and limitations

Assumptions

  1. The classification of the ad (obligation, level, ⋀/⋁) follows the rules in cues.json. Flagged ambiguities in the ad:
    • and_or (I10) „Strong proficiency in Python and/or Java (Spring Boot)“ – 'and/or' read as inclusive OR (⋁).
    • oklepaj_brez_eg (I10) „Strong proficiency in Python and/or Java (Spring Boot)“ – A parenthesised list without 'e.g.' is read as a specification of the concept, not as separate obligations.
    • oklepaj_brez_eg (I10) „working knowledge of JavaScript/TypeScript (Angular, Node.js)“ – A parenthesised list without 'e.g.' is read as a specification of the concept, not as separate obligations.
    • oklepaj_brez_eg (I11) „Practical experience with ML frameworks and libraries (TensorFlow, PyTorch, Scikit-learn, NumPy, Pandas)“ – A parenthesised list without 'e.g.' is read as a specification of the concept, not as separate obligations.
    • including (I12) „Strong grounding in modern engineering practices including Git, CI/CD, testing, code reviews, agile delivery, application resiliency, and security“ – A list after 'including' is read as constituent parts (AND).
    • including (I13) „Experience designing API-first, microservices-based and event-driven architectures, including data engineering patterns for AI systems“ – A list after 'including' is read as constituent parts (AND).
    • oklepaj_brez_eg (I17) „Experience in data science (statistical modeling, experimentation)“ – A parenthesised list without 'e.g.' is read as a specification of the concept, not as separate obligations.
    • range_years (I18) „6–10 years of progressive software engineering experience“ – Year range (e.g. 6–10) read as a lower threshold (≥ min); the upper bound is NOT exclusionary.
    • and_or (I18) „2+ years focused on AI software development, LLM-based solutions, agentic systems, and/or machine learning“ – 'and/or' read as inclusive OR (⋁).
    • degree_implication (I19) „Bachelor's or Master's degree in Computer Science, AI, Robotics, or a related quantitative discipline“ – A Master's normally includes a Bachelor's; the logic keeps A⋁B and the minimal form reveals this.
  2. The 1–4 scale and the cue lexicon (cues_sl.json): e.g. „odlično obvladam“ (“excellent command of”) = 4, „znanje obsega“ (“knowledge covers”) = 2. Another assessor could grade the same texts differently.
  3. A stated level is a lower bound: a level below the requirement gives U, not F. F arises only from an explicit negation or an exact number of years.
  4. Three-valued (Kleene) logic. The formulas are monotone and each letter occurs once, so Kleene agrees with the D/O test (verified 190/190).
  5. The selection policy P1–P3 (below) is not part of the ad and must be approved by the hiring party.
Selection policy
  • P1 A candidate whose root T_M = F (proven NOT to meet mandatory requirements) is excluded.
  • P2 If any candidate has T_M = T, that candidate is selected; ties are broken by satisfied atoms in T_N, then T_P.
  • P3 If no candidate has T_M = T, TREE selects nobody as suitable. Among non-excluded candidates a PRIORITY candidate for verification is ranked by: (1) number of mandatory items = T, (2) number of mandatory atoms = T, (3) fewer mandatory atoms = F, (4) T_P, (5) T_N.

Missing inferences

The mandatory atoms without evidence are listed on each candidate card; for T_M = T every one of them would have to become T. The most common gaps for everyone are education (a48–a50), enterprise-scale production (a47), Git/testing/code reviews (a21–a24) and OpenShift (a34).

Limitations

  • The facts were extracted by a language model (Claude (claude-opus-5-5), 2026-09-24). Only the verbatim presence of each quote is checked mechanically.
  • The viewer accepts at most 4 variables, so the tree is split into 19 formulas. The proof of the root is a chain of proofs, not a single formula.
  • Engine: MinimalneNormalneForme checks the string 'tautology;)!)' while PrimeImplicants returns 'tautologija;)!)' → every tautology raises ClassCastException (verified on A⇒A, A⋁¬A, (A⋀B)⇒(A⋁B)). All proofs are therefore expressed as contradiction checks.
  • Engine: The README states Java 8+, but common/UIStrings.java requires Java 15+ (text blocks); the engine does not compile on a machine with Java 11.
  • The engine was run in a cloud sandbox (openjdk version "21.0.10" 2026-01-20); it cannot be compiled on a machine with Java 11.
  • A hiring decision based solely on automated processing would likely trigger rules on automated decision-making (e.g. GDPR Art. 22); human review is therefore required.

  • Za vsako od 190 kombinacij (vozlišče × kandidat × način) je izvirni pogon propMinimization (parser + DNF + primarni implikanti) ugotovil protislovje oz. zadovoljivost ustrezne formule. Ujemanje z neodvisnim Python/Kleene izračunom: 190/190.
